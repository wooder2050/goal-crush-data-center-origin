# 애드센스 기준선 (수동 광고 칸 적용 전)

수동 광고 칸(`src/components/AdSlot.tsx`) 효과를 판정하기 위한 적용 전 수치.
출처: GA4(애드센스 연동) `screenPageViews`, `publisherAdImpressions`, `totalAdRevenue`(KRW).

## 판정 규칙

- 수익 공식: `수익 = PV × 페이지 RPM / 1000`, `페이지 RPM = 노출/PV × 노출 RPM`. 두 식을 섞어 곱하지 않는다.
- 1차 목표: 전체 페이지 RPM **₩156 → ₩468 이상**(7월 대비 3배).
- URL군별로 적용 전후 각각 **최소 1,000 PV**가 쌓인 뒤 비교한다. 모자라면 판정 보류.
- 모바일 참여율이 10% 이상 떨어지면 해당 위치를 옮기거나 뺀다.
- **2026-07-31 ~ 08-26은 제외한다.** 이 기간엔 GA 설정 스크립트가 실행되지 않아 GA 집계가 끊겼다.
- "랜딩" = `pagePath == landingPage`인 PV(첫 진입), "사이트 안 이동" = 나머지.
- 애드센스 콘솔의 광고 단위별 보고서(수동 칸 4개)와 GA 수치를 월 1회 대조한다. 두 제품의 PV 정의가 달라 절대값은 다를 수 있으니 추세만 비교한다.

## 관찰

1. 사이트 안에서 이동한 PV는 홈(기준선 A 0.110)을 빼면 모든 URL군에서 노출/PV가 0.00~0.02다. 자동광고는 첫 로드 페이지에만 광고를 채우는 것으로 보인다. 전체 PV의 약 70%가 사이트 안 이동이다.
2. 수동 칸을 넣는 상세 4종(경기·시즌·선수·팀)은 기준선 A에서 PV 10,469(전체의 38%)지만 페이지 RPM이 ₩3~51이다.
3. 목록형 페이지(`/players`, `/teams`, `/matches`)는 랜딩이어도 노출/PV가 낮다. 자동광고가 이 레이아웃에 광고를 잘 넣지 않는다.

## 적용 후 확인 방법

1. 적용 직후 브라우저에서 같은 상세 URL을 (a) 직접 새로고침, (b) 홈에서 링크로 이동 두 방식으로 열고, 둘 다 `ins.adsbygoogle`에 `data-ad-status="filled"`가 붙는지 본다.
2. URL군별 1,000 PV가 쌓이면 위 표와 같은 방식으로 다시 집계해 "사이트 안 노출/PV"와 페이지 RPM을 비교한다.
3. 애드센스 콘솔 > 광고 단위별 보고서에서 `matchDetail`·`seasonDetail`·`playerDetail`·`teamDetail` 단위의 노출·RPM을 확인한다.
